# DSN-like 0.2.2 — capability-driven tools and patch workflow

This checkpoint advances code-only work before hardware validation.

## Engine capabilities
Engines now expose tool capabilities explicitly. Lyra/Legacy default to WaveTypeSelector. DSN-like advertises PatchEditor, PatchBank, DualVCO, FM, HardSync and DedicatedDrums, and deliberately does not expose WaveTypeSelector. `ChiptuneEngineBuild.WaveTypes` is nullable and is only populated when the engine advertises that capability.

## Patch model
The DSN state model is explicit: GM Program -> assigned patch id -> immutable Factory patch or named User Patch -> Working Patch in the editor. Program Change selects a patch for future notes; sounding voices keep their patch.

## Storage
User patches and GM assignments are stored separately from Factory patches in `dsnlike-bank-v2.json`. Factory is generated by code and is never overwritten. The bank schema is versioned. `DsnPatchStorage` adds a versioned `midirift.dsn.patch` document, range validation and import/export primitives for future file-picker UI.

## Editor
The dedicated DSN editor now distinguishes assigned vs working state and exposes Save, Save As, Duplicate, Rename, Delete User Patch and Reset to Factory. Reset only removes the GM assignment; it does not destroy the reusable user patch. Dirty state is shown explicitly.

## Hardware gate
This source checkpoint has not been compiled or auditioned in the Android target environment. First hardware pass should compile before any DSP tuning.
